前綴和

前綴和陣列建構與區間查詢公式

A10-01-PrefixSum
點標題可以展開或收合

1學習目標

  • 知道什麼時候該用前綴和：題目要重複查詢某一段區間的總和時。
  • 會建立「累積總額清單」，並用公式直接算出任何一段區間的總和，不用每次重新加總。
  • 會把前綴和公式套用在平均值、扣除單點、反向搜尋等變化題型上。

2概念說明

如果題目只問一次「第L天到第R天的總和」，直接用迴圈加總就好。但如果要重複查詢很多次，每次都重新加總會很浪費——資料量一大，重複計算的次數也跟著暴增。

前綴和的做法是：先花一次功夫，把「從第1天累加到第i天」的總額，依序存進一份清單（累積總額清單）。之後不管要查詢哪一段區間，都只要做一次減法：

區間[L, R]的總和 = 累積總額清單第R項 − 累積總額清單第(L-1)項
你想做的事用哪個積木
建立累積總額清單「清單中加入」，每一項＝前一項加上這一天的金額
查詢區間[L, R]的總和清單第R項 − 清單第(L-1)項
避免L=1時減到第0項累積總額清單第0項先放0（代表「累加到第0天」什麼都還沒加）
💡 第0項是關鍵

累積總額清單要多存一項「第0項＝0」，這樣查詢L=1開始的區間時，公式「第R項−第(L-1)項」才不會存取到不存在的「第0項之前」。可以把累積總額清單想成「比原始資料多一格，位移一個位置」。

第 1 步：讀題，找出輸入和輸出
  • 輸入：天數N、N個每日募款金額。
  • 輸出：N個數字，依序是第1天到第i天的累積總額。
第 2 步：把問題拆成步驟
將 累積清單 設為空清單
清單中加入 0（代表累積到第0天）
循環計數 i 從 1 到 N 每次增加 1
    將 這天累積 設為 (累積清單的第 i 項) + (募款清單的第 i 項)
    清單中加入 這天累積
說出 累積清單（去掉第0項之後的所有內容，用空白接起來）
第 3 步：用範例走一次

輸入「4」「100 200 150 50」：

i募款清單第i項累積清單第i項（＝前一項+這項）
0—0（起始）
11000+100=100
2200100+200=300
3150300+150=450
450450+50=500

輸出「100 300 450 500」，和範例一樣。

第 4 步：解法詳解

這題本身就是在建立前綴和的基礎結構，之後所有練習題都是在這份累積清單上做文章：

  • 累積清單的第i項，代表「第1天到第i天」的總和。
  • 每一項都是「前一項」加上「這一天新增的金額」——這就是「累積」兩個字的意思，不用每次從頭加總。
  • 第0項放0，是為了讓之後查詢「從第1天開始」的區間時，公式仍然成立（見下面常見錯誤）。
⚠️ 常見錯誤
  • 忘記放第0項：直接從第1天開始存，之後查詢區間時公式會對不起來，要特別處理L=1的情況，不如一開始就多放一個0。
  • 輸出格式少了最後一項或多了第0項：題目只要輸出N個累積總額（第1項到第N項），不要把第0項也印出來。

遊戲關卡的積分計算

L4｜精熟W9-06
這題多了什麼：情境換成遊戲關卡分數，但技巧跟練習M3-02-02完全一樣：建累積清單，查詢時用公式直接算，不用重新加總——這題還特別在題目裡明講「請試著思考如何先將資料整理好」，就是在暗示要用前綴和。
看題目內容
小明在玩一款闖關遊戲，共有 N 個關卡，每個關卡通過後都會獲得對應的分數。 遊戲結束後，系統會進行多次「回顧分析」，頻繁詢問小明在「第 L 關 到 第 R 關」之間總共獲得了多少分。 【提示】雖然查詢次數變少了，但依然請試著思考如何「先將資料整理好（例如使用前綴和）」，讓每一次的查詢都能更有效率地給出答案。
輸入
• 系統的第一個輸入包含：先是兩個整數 N、Q（1 ≤ N ≤ 100,000，1 ≤ Q ≤ 3），代表關卡總數與查詢次數。接著是 N 個整數，代表第 1 關到第 N 關的得分（0 ≤ 分數 ≤ 1,000）。所有數字之間皆以單一空白隔開。 • 接下來有 Q 個輸入（系統的第二至第四個輸入），每個輸入包含兩個整數 L 與 R，代表要查詢「起始關卡」與「結束關卡」的區間（1 ≤ L ≤ R ≤ N）。
輸出
• 針對每一次的區間查詢，請輸出一個整數（該區間的總分），每個答案獨立換一行輸出。

6自我檢核

學完之後，檢查看看你能不能做到這些事。有做不到的，就回到上面對應的地方再看一次。

  • 我知道前綴和適合用在「要重複查詢很多段區間總和」的題目。
  • 我會建立累積總額清單，並且記得多放一個「第0項＝0」。
  • 我會用「清單第R項 − 清單第(L-1)項」的公式直接算出任何區間的總和。
  • 我會在前綴和的基礎上，進一步算平均值、扣除單點、或反向找出符合條件的區間。
